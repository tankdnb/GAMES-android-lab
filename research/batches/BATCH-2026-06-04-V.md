## Working Notes

- Main question for this batch is whether `ktaf` still adds enough distinct value after `ktvn`, or whether it should be kept only as a comparison reference because of overlap and narrower Android transfer.
- Initial selection reasons:
  - explicit MIT licensing
  - still-maintained niche Kotlin game framework
  - a simpler text-adventure baseline from the same author ecosystem as `ktvn`
  - likely reusable ideas around DSL shape, progression runtime, and content/host separation
- Final verdict: `accepted`
- Why:
  - `ktaf` remains distinct enough from `ktvn` to justify a main-catalog entry because it focuses on parser-driven exploration, room graphs, item interactions, contextual command parsing, and swappable IO/render hosts
  - the strongest reusable seams are `IOConfiguration` plus frame builders, `RegionMaker` plus `OverworldMaker`, the layered command interpreters, and the jar-based `GameTemplate` discovery path
  - Android transfer stays indirect and narrow, but the framework is still a good Kotlin reference for narrative-heavy or exploration-heavy games that need a replaceable host UI shell
