## Working Notes

- Main question for this batch is whether `tripeaks-gdx` is only a finished small card game or whether it contains reusable Kotlin or libGDX patterns around board state, input, animation flow, persistence, and Android-transferable product structure.
- Initial selection reasons:
  - explicit GPL-3.0 licensing
  - materially stronger public signal than the other refreshed-shortlist candidates
  - enough recency to avoid a purely historical pass
  - likely good balance between gameplay-complete code and manageable repository size
- Final verdict:
  - `accepted`
  - `TriPeaks` is small, but it is a real reusable Android and libGDX reference thanks to its layout-graph rules core, pooled view synchronization, JSON persistence with legacy migration, and practical Android plus desktop packaging split.
  - The main caveats are a missing automated test surface, no checked-in CI workflows, a README that now points readers to a newer reimplementation, and the current lab JVM being too old to configure AGP `8.5.2`.
