## Working Notes

- Main question for this batch was whether `la-bomba` had enough implementation depth beyond Firebase/product integration to belong in the main catalog despite zero public signal.
- Final verdict: `accepted`.
- Why:
  - the repository is not an engine or real-time networking baseline, but it is a solid direct-Android product-shell reference for anonymous Firebase bootstrap, cloud-backed user-authored content, fragment-hosted setup, timer-driven rounds, and compact rematch handling
  - the inspected code makes it clear that "multiplayer" here means local pass-the-device play with synced content collections rather than a synchronized online match, which is still useful but should be documented precisely
  - the repo is weak on tests and public signal, yet the Android-specific implementation surface is current enough and concrete enough to preserve in the main catalog
- Main reusable seams confirmed during the pass:
  - `BaseActivity.kt`, `MainActivity.kt`, `SettingsActivity.kt`, `StartGameActivity.kt`, and `ResultsActivity.kt`
  - `GameSession.kt`
  - `FirebaseAuthManager.kt`, `FirestoreConfig.kt`, `PenaltyDbManager.kt`, `PlayerDbManager.kt`, and `TopicDbManager.kt`
  - `TopicsFragment.kt` and the step-by-step fragment wizard
  - `AdsManager.kt` plus the manifest-level Android service wiring
