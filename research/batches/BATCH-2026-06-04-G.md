## Working Notes

- Main question for this batch: whether `ktvn` is a narrow JVM-only story framework or a broader Kotlin game-architecture reference worth keeping in the lab.
- Expected hotspots before cloning: DSL surface, scene/state flow, asset or script loading, save/progression model, samples, tests, and build/publishing automation.
- Final verdict: `accepted`
- Main reasons:
  - the repository combines a real narrative DSL, typed branching runtime, host-agnostic engine adapters, split persistence, and unusually broad unit coverage for a niche Kotlin game library
  - direct Android transfer is indirect, but the architecture is still strong enough for story-heavy Kotlin/Android games to justify keeping it in the main catalog
- Main caveats:
  - JVM-only checked-in host surfaces, README still labels the DSL as early-stage, and local Gradle validation in the lab remains blocked by the Java `8` environment while upstream expects JDK `11+`
