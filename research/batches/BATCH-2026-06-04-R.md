## Working Notes

- Main question for this batch is whether `kool-engine/kool` should be treated as a major Android-relevant engine reference, or as a broader graphics/engine architecture reference with only indirect Android transfer today.
- Initial selection reasons:
  - explicit Apache-2.0 licensing
  - very fresh code activity on `2026-06-03`
  - materially higher star signal than the refreshed alternatives
  - explicit Android plus Vulkan/WebGPU/OpenGL targets, which should create strong reusable findings around renderer/runtime partitioning
- Final verdict: `accepted`
- Why:
  - the repository is much more than a graphics toy; it has a real multiplatform runtime, platform contexts, embedded UI, editor modules, two physics layers, and concrete Android source sets
  - Android is not the default contributor path because the Gradle surface disables it until `enableAndroidPlatform` is run, but the checked-in Android context, input, asset, and backend code make it a direct Android-relevant engine reference rather than a desktop-only comparison sample
  - the build/toolchain story is heavy, but it is explicit and well-documented: Gradle `17+`, common JDK `25`, and `wgpu4k`-specific Java `22`
- Main reusable seams confirmed during the pass:
  - `KoolContext.kt`, `Scene.kt`, `Lwjgl3Context.kt`, and `KoolDispatchers.kt`
  - `RenderBackend.kt` and the platform backend trees
  - `UiSurfaceComposition.kt` and the demo-side `LaunchedEffectTest.kt`
  - `PhysicsWorld.kt`, `Physics2dWorld.kt`, and the platform transform tasks in `kool-physics/build.gradle.kts`
  - `KoolContextAndroid.kt`, `KoolSurfaceView.kt`, `KoolConfigAndroid.kt`, `PlatformInput.android.kt`, and `Assets.android.kt`
