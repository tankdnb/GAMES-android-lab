## Working Notes

- Main question for this batch is whether `BlueBoxWare/LibGDXPlugin` belongs in the main catalog as a reusable game-development tooling reference, or whether it is too IDE-specific and should stay only as a comparison note.
- Initial selection reasons:
  - explicit Apache-2.0 licensing
  - fresh code activity on `2026-05-29`
  - solid public signal at `158` stars for a Kotlin-heavy game-dev plugin
  - likely reusable value around project generation, run/debug flows, and LibGDX-specific IDE automation
- Final verdict: `accepted`
- Why:
  - the repository is more valuable than the initial shortlist wording suggested: it is not mainly a project generator, but a broad semantic tooling layer for libGDX projects covering asset references, Skin/JSON/atlas/tree editors, Android correctness inspections, previews, and screen scaffolding
  - Android relevance is indirect but still strong for libGDX teams working in Android Studio because the plugin encodes real manifest, asset, and editor ergonomics that reduce recurring mistakes
  - the checked-in test surface is substantial, with fixture-driven inspection and asset tests rather than only plugin smoke checks
- Main reusable seams confirmed during the pass:
  - `plugin.xml`, `build.gradle.kts`, and `LibGDXProjectFileSubstitutions.kt`
  - `AssetReferenceProvider.kt`, `KotlinReferenceContributor.kt`, `FileReference.kt`, and `AnnotationUtils.kt`
  - `SkinCompletionContributor.kt`
  - `ImagePreviewDocumentationTarget.kt`
  - `OpenGLESDirectiveInspection.kt` and the XML inspection set
  - `TreeCompletionContributor.kt` and `TreeUnknownClassInspection.kt`
  - `TestInspections.kt` and `TestAssetUtils.kt`
