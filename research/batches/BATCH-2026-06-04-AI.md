## Working Notes

- Main question for this batch is whether `FriceEngine` still earns catalog space as a legacy Kotlin game-engine reference, or whether it should stay only as a niche comparison point because of age, JVM-only scope, and AGPL constraints.
- Initial selection reasons:
  - explicit `AGPL-3.0` licensing
  - unusually strong historical signal for this niche at `349` stars
  - explicit Kotlin JVM engine intent with Swing/JavaFX surface
  - compact enough to finish as a static-first legacy-architecture pass
- Final verdict:
  - `reference-only`
  - `FriceEngine` is worth keeping as a historical Kotlin engine comparison point because it exposes a clean dual-backend drawer/image seam, buffered layer mutation, and tiny event/resource helpers.
  - It does not hold up as a main catalog baseline for Android work: there is no Android target, the build now breaks on legacy Bintray-era dependencies, the runtime is tied to Swing/JavaFX, and a few concrete maturity issues are visible directly in the checked-in code.
